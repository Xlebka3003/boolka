# Диагностика boolka

После ошибки откройте шестерёнку → «Сохранить журнал» (Save diagnostic log).
Выберите место для ZIP. Результат сохранения показан в окне настроек.
Просмотрите текстовые файлы внутри архива перед отправкой и передайте ZIP разработчику вместе с описанием действий перед ошибкой.

## Что записывается

- Дата UTC, версия boolka, случайный идентификатор запуска.
- Версия Windows, .NET и архитектура процесса.
- Начало и завершение сеанса, этапы сканирования и операций, ошибки интерфейса/каталога/установки/резервных копий.
- Тип исключения, HResult, ограниченное сообщение и технический стек без путей исходников; вложенные ошибки в ограниченном количестве.
- Для создания копии отмечены этапы копирования, проверки и публикации, чтобы можно было установить причину оставшейся creating-папки.

Файлы находятся в `%LOCALAPPDATA%/boolka/logs`. Записывается не более1МиБ на файл, сохраняются8последних файлов с автоматической ротацией. Очистка выполняется по возможности: файлы, занятые другим процессом, могут остаться до следующей ротации.

## Приватность

Записывается только техническая диагностика. Содержимое AddOns, SavedVariables, файлов настроек, описаний модов, сетевых ответов и дампы памяти не копируются в отчёт. Пути Windows/UNC, ссылки с параметрами, email и известные имя пользователя/компьютера маскируются до записи; типичные поля паролей и токенов также скрываются. При экспорте выполняется повторная фильтрация.

ZIP включает только отобранные файлы журналов, сведения о среде и краткую инструкцию. Ничего не загружается на сервер и не отправляется автоматически. Маскирование не является гарантией удаления любых возможных личных сведений из произвольного текста ошибки, поэтому перед передачей отчёт стоит просмотреть.

## Аварийные завершения

Обработчики подключены до загрузки XAML: ошибки UI-потока, необработанные managed-исключения процесса и необслуженные ошибки задач. При зарегистрированном фатальном исключении запись сбрасывается на диск и создаётся короткая отметка; следующий запуск предлагает сохранить журнал. Неизвестная ошибка не объявляется обработанной — приложение не пытается продолжать потенциально небезопасную работу.

Отключение питания, принудительное завершение процесса, некоторые нативные сбои и нехватка памяти могут не дать записать последнюю ошибку. При недоступном диске или отсутствии прав полноценный журнал также может быть недоступен. Сбой подсистемы диагностики не подменяет исходную ошибку приложения.

## Проверка

Приватность, экспорт, пределы размера, ротация, параллельные записи, отметка аварии и отсутствие влияния ошибок логирования проверены на тестовых данных. Фатальная запись проверялась прямым вызовом обработчика записи без намеренного аварийного закрытия приложения пользователя. Проверки окон выполнялись скрыто.
