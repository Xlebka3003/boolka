# Обновление приложения boolka

## Для пользователя

При запуске и затем раз в час boolka тихо проверяет последний стабильный выпуск GitHub. Черновики, предварительные и более старые версии не предлагаются. Новая версия подсвечивает кнопку с круговыми стрелками. В подсказке указан её номер. Уведомлений и автоматического скачивания нет.

Нажатие кнопки загружает Windows x64 ZIP, проверяет размер, SHA256 из API GitHub, имена и состав файлов, а также версию EXE. Пока выполняется операция с модами, кнопка недоступна. Затем приложение закрывается; его временная копия заменяет только EXE и семь файлов лицензий и запускает новую boolka. Установщик для этого не нужен: один механизм работает для установленной и ZIP-версии.

Настройки, AddOns, SavedVariables, игровой профиль и посторонние файлы в папке приложения не заменяются. Файлы удаления установщика сохраняются. Предыдущие файлы и журнал остаются в скрытой папке `.boolka-update-<id>` внутри папки программы. При ошибке замены выполняется откат; незавершённая транзакция восстанавливается отдельным помощником до обычного запуска. При неудаче уже начатого обновления показывается ошибка с расположением диагностических файлов. Тихой остаётся именно проверка доступности новой версии.

Нужен доступ на запись в папку программы. Распакуйте ZIP в доступную для записи папку. Если приложение вручную перенесли в защищённую папку, распакуйте новый ZIP в доступную папку. Программа сама не запрашивает повышение прав. Встроенное обновление не работает в процессе, запущенном от администратора: перезапустите boolka обычным способом или обновите вручную из ZIP.

## Что загрузить в GitHub Release

1. Создайте обычный опубликованный выпуск с тегом `v<версия>`, например `v0.41.9`. Версия должна совпадать с EXE. Выберите его последним выпуском; не помечайте как draft или prerelease.
2. Прикрепите **оба файла** из подготовленной папки: `boolka-<версия>-windows-x64-standalone.zip` и `boolka-<версия>-SHA256SUMS.txt`. Не переименовывайте ZIP и не добавляйте в него внешнюю папку.
3. Для работы без входа пользователей в GitHub репозиторий `Xlebka3003/boolka` и файлы релиза должны быть доступны публично. В boolka нет личных GitHub-токенов и входа в аккаунт. Закрытый репозиторий, отсутствие подходящего выпуска или ошибка сети оставляют кнопку обычной; подробности ошибки сети записываются только в журнал.
4. GitHub предоставляет SHA256 загруженного asset в API. Без корректного digest boolka не предлагает скачивание. Проверяется ZIP, а не автоматически создаваемые GitHub архивы исходников.

Первую версию с этим механизмом нужно установить вручную. Кнопка в 0.41.9 подсветится только после публикации **более новой** версии, например 0.41.10. Публикация самой 0.41.9 не создаёт обновление для неё же.

Исходник адреса репозитория: `ApplicationReleaseClient.Repository`. Если исходники остаются закрытыми, перед публичным выпуском можно отдельно согласовать публичный репозиторий с готовыми сборками и сменить этот адрес. Видимость существующего репозитория приложение не меняет.

## Для сборки

Упаковщик: `scripts/Package-Windows.ps1`, инструкция: `INSTALLING.md`. GitHub Actions `Windows release` запускается **только вручную** через Run workflow; обычный push сам по себе больше не создаёт релиз. Workflow собирает и проверяет приложение, готовит ZIP/SHA256 и публикует их. Уже существующие выпуски и локальные пакеты не перезаписываются.

Проверки обновления: `dotnet build tests/ApplicationUpdates/ApplicationUpdates.csproj -m:1`, затем `dotnet run --project tests/ApplicationUpdates/ApplicationUpdates.csproj --no-build`. Проверки используют поддельный HTTP и отдельные файлы/тестовые EXE; не запускают настоящую boolka и не меняют пользовательские моды. Реальный переход между двумя опубликованными версиями проверяйте в Windows Sandbox.
